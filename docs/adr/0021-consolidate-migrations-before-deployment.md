# ADR-0021: 배포 전 마이그레이션 통합

## 상태

Accepted (2026-10-08). [ADR-0008](0008-repository-conventions.md)의 "적용된 마이그레이션 파일은 수정하지 않는다" 규칙을 배포 전까지 완화한다.

## 배경 (Context)

서비스가 아직 배포되지 않아 영속 데이터가 있는 환경이 없는데도 규칙에 따라 컬럼 이름 변경(V3)과 인덱스 추가(V4) 같은 변경이 새 파일로 쌓이고 있었다. 인덱스가 테이블 정의 안에 인라인으로 섞여 있어 역할별로 읽기도 어려웠다.

## 결정 (Decision)

1. **서비스를 처음 배포하기 전까지는 마이그레이션 파일을 합치거나 고칠 수 있다.** 첫 배포(영속 데이터가 생기는 첫 환경, 스테이징 포함) 이후에는 적용된 파일을 수정하지 않고 새 버전 파일을 추가한다. 첫 배포 시점에 이 ADR을 `Superseded`로 바꾸고 ADR-0008의 규칙을 되살린다.
2. **마이그레이션은 역할별 세 파일이다.** `V1__create_schema.sql`은 테이블·유니크·CHECK, `V2__add_indexes.sql`은 인덱스, `V3__add_foreign_keys.sql`은 외래키다. 인덱스를 외래키보다 먼저 만들어 MySQL이 외래키용 인덱스를 자동으로 만들지 않게 한다. V2는 외래키를 뒷받침하는 인덱스와 조회·스캔 성능용 인덱스를 주석으로 구분한다.
3. **기존 V3(`ims_quantity` → `inventory_quantity`)와 V4(`idx_inventory_product`)는 없애고** 컬럼은 V1에서 처음부터 올바른 이름으로 정의하고 인덱스는 V2에 둔다.
4. **합친 결과가 이전과 같은 스키마인지 확인했다.** 이전(V1~V4)과 이후(V1~V3)를 별도 MySQL에 적용해 컬럼(타입·널·기본값·문자셋·collation), 인덱스(이름·컬럼 순서·유니크 여부), CHECK, 외래키를 비교했고 차이가 없었다. `MigrationStructureTest`가 일반 인덱스 16개의 이름과 컬럼 순서, 외래키 12개, 컬럼 이름을 계속 확인하며, 외래키가 자동으로 만든 인덱스가 끼면 실패한다.
5. **이미 이전 마이그레이션이 적용된 로컬 DB는 Flyway 체크섬 검증에 실패한다.** `docker compose down -v`로 볼륨을 지우고 다시 만든다. CI와 Testcontainers는 매번 새 DB라 영향이 없다.

## 결과 (Consequences)

- 얻는 것: 마이그레이션이 테이블 → 인덱스 → 외래키로 읽히고 이름 변경이나 추가 인덱스 같은 임시 파일이 사라진다. 외래키용 인덱스가 자동 생성되지 않는다.
- 감수하는 것: 로컬 개발 DB를 한 번 다시 만들어야 한다. 첫 배포 시점을 놓치면 수정 금지 규칙이 풀린 채로 남을 수 있어 그 시점에 이 ADR을 닫는 것을 잊지 않아야 한다. ADR-0018·0020의 V3·V4 언급은 이 결정으로 달라졌다(각 ADR 상태에 표시).
