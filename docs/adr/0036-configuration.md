# ADR-0036: 설정과 운영 프로필

## 상태

Accepted (2026-10-12). 배포 플랫폼이 정해지지 않아 플랫폼에 중립인 규칙만 정한다.

## 배경 (Context)

`application.yaml`에는 로컬 개발을 편하게 하려는 기본값(`localhost`, `root`, 로컬 Kafka·인증 서버 주소)이 있다. 운영에서 환경변수를 하나 빠뜨리면 이 기본값으로 조용히 `localhost`에 연결하려 해서, 원인을 찾기 어려운 장애나 잘못된 대상 연결로 이어질 수 있다. 또 운영에서 조정해야 하는 값(풀 크기, 배치 간격, 승인 임계치)을 어떻게 바꾸는지가 문서화되어 있지 않았다.

## 결정 (Decision)

1. **운영 프로필(`prod`)을 둔다.** `application-prod.yaml`이 DB, Kafka, 인증 서버 주소의 로컬 기본값을 없애 필수 환경변수가 없으면 기동 단계에서 실패하게 한다(`DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`, `KAFKA_BOOTSTRAP_SERVERS`, `AUTH_ISSUER_BASE_URI`). 비밀번호는 기본 설정에서도 기본값이 없다. `local`과 `prod`를 함께 켜면 막는 기존 가드(`LocalProfileGuard`)는 그대로다.
2. **`WMS_BASE_URL`과 system client 자격은 필수로 두지 않는다.** WMS 연동은 WMS가 준비된 뒤에 켤 수 있어야 하고, 없으면 대사 실행이 `FAILED`로 기록될 뿐 다른 기능은 영향이 없다.
3. **조정이 필요한 값은 환경변수로 덮어쓴다.** 설정 파일을 환경별로 따로 두지 않고, 속성 이름을 점과 하이픈을 밑줄로 바꾼 대문자로 쓰는 규칙(맵 항목은 하이픈을 뺀 이름)을 문서화한다(`docs/configuration.md`). 이 규칙은 테스트로 확인한다.
4. **맵 형태의 설정(카테고리별 임계치, 채널별 TTL)은 키의 대소문자를 구분하지 않는다.** 환경변수로 넘기면 키가 소문자가 되어 `BEAN`으로 찾으면 설정이 무시되는 문제가 있었다.
5. **스케줄러의 여러 인스턴스 안전성을 문서화한다.** 각 배치가 어떤 장치(락, 조건부 갱신, 멱등 키)로 중복을 막는지와 스케일 아웃 때의 주의점(파티션 수, 커넥션 수, 최초 마이그레이션)을 적는다.

## 결과 (Consequences)

- 얻는 것: 운영에서 환경변수를 빠뜨리면 바로 기동 실패로 드러난다. 조정 가능한 값과 바꾸는 방법이 한 문서에 있다. 환경변수로 넣은 카테고리·채널 설정이 대소문자 때문에 무시되지 않는다.
- 감수하는 것: 운영 환경은 `SPRING_PROFILES_ACTIVE=prod`를 반드시 설정해야 한다(설정하지 않으면 로컬 기본값으로 동작한다). 채널·카테고리 키가 대소문자만 다른 두 설정은 구분할 수 없다.
