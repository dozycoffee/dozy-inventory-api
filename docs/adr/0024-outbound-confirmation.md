# ADR-0024: 출고 확정 반영 규칙

## 상태

Accepted (2026-10-08). 구현은 계층별 PR로 나눈다: (1) inventory의 출고 반영 UseCase와 reservation 도메인·영속성, (2) 출고 확정 application, (3) 웹 어댑터.

## 배경 (Context)

F-012는 WMS의 출고 확정을 재고에 반영한다. 예약은 확정(`CONFIRMED`)된 뒤 WMS가 Lot별 수량으로 출고를 지시하고(ADR-0023), 출고가 끝나면 총 수량과 예약 수량을 함께 줄이고 예약을 `FULFILLED`로 바꾼다(원칙 12: 출고 확정 이후는 추적하지 않는다). 시나리오 6.1이 레포로 이식되기 전이라 요청 단위, 부분 출고, 결품 처리를 정해야 했다.

## 결정 (Decision)

1. **요청 단위는 예약 하나이다.** `POST /api/v1/reservations/{id}/fulfillment`(웹 어댑터 PR). 본문은 예약의 **모든 할당 재고 행**에 대해 재고 행 ID와 실제 출고 수량을 한 번씩 담는다. 빠지거나 중복되거나 할당 수량을 넘거나 음수이면 400(`INV_INVALID_FULFILLMENT`)이다. 0은 허용한다(그 Lot에서는 하나도 출고하지 못함).
2. **출고 확정은 예약당 한 번, 전체로만 한다.** 확정(`CONFIRMED`)된 예약만 대상이고 성공하면 바로 `FULFILLED`가 된다. 여러 번에 나눠 출고하는 부분 출고는 없다(WMS가 피킹을 마친 뒤 최종 수량을 한 번에 보낸다). 확정 전·해제·만료된 예약은 409(`INV_INVALID_RESERVATION_STATE`)이다.
3. **결품은 입력으로 받아 남은 예약을 자동 해제한다.** 재고 행별 결품 = 할당 수량 − 출고 수량이다. 출고한 수량만큼 총 수량과 예약 수량을 함께 줄이고(`ship`), 결품 수량은 **예약 수량만** 되돌려 가용으로 돌린다(`release`). 결품은 실물이 모자란 것이라 총 수량은 줄이지 않는다. 원인(분실, 재고 불일치)은 실사 조정(F-015)과 대사(F-019)로 정리한다(원칙 7: 물리 사실은 WMS가 기준이고 사람이 확인한 뒤 맞춘다). 결품 수량은 `reservation_event`(`FULFILLED`)의 상세에 남긴다.
4. **이력**: 출고 수량이 0보다 큰 재고 행마다 `OUTBOUND` 이력(변동량 −출고 수량, 처리 후 총 수량, 원인 문서 `RESERVATION`/예약 ID)을 남긴다. 예약 수량만 되돌리는 행은 총 수량이 바뀌지 않아 이력이 없다.
5. **멱등 키는 `Idempotency-Key` 헤더이다**(수량을 바꾸는 요청이므로 ADR-0019와 같은 규칙). 이력의 `(멱등 키, 재고 행)` 유니크 제약이 같은 키의 재고 행 중복 반영을 막는다. 같은 키의 재요청은 예약이 이미 `FULFILLED`이고 요청한 출고 수량이 기록된 값과 같으면 아무것도 바꾸지 않고 처음과 같은 결과(처리 후 수량은 키로 이력을 다시 조회)를 반환한다. 수량이 다르면 409이다. 최종 판정은 `CONFIRMED` → `FULFILLED` 조건부 UPDATE이다.
6. **응답은 재고 행별로 할당·출고·결품 수량과 처리 후 총 수량을 준다.** WMS가 자기 수량과 즉시 비교한다(시나리오 결정 8). 출고가 0인 행은 총 수량이 바뀌지 않아 처리 후 수량이 없다(null).
7. **호출은 `inventory:service`만 허용한다**(WMS는 system client). 트랜잭션의 잠금 순서는 예약 행 → 재고 행 `inventory_id` 오름차순이다(ADR-0023 결정 11과 같다).

## 결과 (Consequences)

- 얻는 것: 출고가 예약과 한 트랜잭션으로 원자적으로 반영되어 중복 차감이 불가능하고, 결품이 있어도 현장이 막히지 않으며(원칙 8) 남은 수량은 즉시 가용으로 돌아온다.
- 감수하는 것: 결품 시 inventory의 총 수량이 실물보다 많은 상태가 실사 조정 전까지 이어진다. 한 예약의 출고를 여러 번에 나눠 보낼 수 없어 WMS가 최종 수량을 모아 보내야 한다. 같은 재고 행의 모든 할당을 한 요청에 담아야 하는 만큼 요청이 길어질 수 있다.
