# ADR-0002: 메시지 브로커는 Kafka, 이벤트는 Outbox로 발행

## 상태

Accepted (2026-10-05)

## 배경 (Context)

IMS는 수량이 바뀔 때마다 이벤트를 발행하고, "DB에 수량 저장"과 "브로커에 이벤트 발행"은 서로 다른 시스템이라 한 번에 성공시킬 수 없다.
`예약 확정` 이벤트가 유실되면 WMS가 출고를 시작하지 않아 결제까지 끝난 주문이 멈춘다.

요건: 구독자가 여럿이고 늘어난다. 유실되면 안 되는 이벤트가 있다(최소 한 번 전달). 같은 상품·Lot 이벤트의 순서가 뒤집히면 안 된다.

고려한 대안: RabbitMQ(순서·재처리가 약함), 클라우드 관리형 SQS/SNS(클라우드 선택에 종속, 순서 보장에 제약), 브로커 선택 보류.

## 결정 (Decision)

- 이벤트를 수량 변경과 같은 트랜잭션으로 `outbox_event`에 저장하고, 별도 프로세스가 Kafka로 발행한다(Outbox 패턴).
- 파티션 키(`창고ID:상품ID`)로 같은 키의 순서를 보장한다.
- 이벤트 발행은 포트로 추상화해 도메인 로직이 브로커에 의존하지 않게 한다.
- 구독자는 멱등 키로 중복을 걸러낸다.

## 결과 (Consequences)

- 얻는 것: 유실 없는 전달, 파티션 키 기반 순서 보장, 과거 이벤트 재생으로 새 구독자 추가가 쉽다.
- 감수하는 것: Kafka 클러스터 운영 부담이 크다. 구독자는 중복 전달에 대비해 멱등 처리를 해야 한다.
