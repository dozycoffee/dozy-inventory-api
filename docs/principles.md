# 서비스 경계와 핵심 원칙

inventory 서비스가 무엇을 하고 무엇을 하지 않는지, 구현 중 판단이 갈릴 때 기준이 되는 원칙을 정리한다.
근거와 대안은 [ADR](adr/README.md)에 있다.

## 1. 서비스 소개

inventory 서비스는 DOZY COFFEE 원부자재 재고의 단일 진실 공급원(SSOT)이다.
**"무엇이 몇 개 있고, 그중 몇 개를 약속할 수 있는가"** 를 책임진다.

- 기존에는 WMS가 창고 작업과 재고를 함께 다뤘다. OMS와 가맹점 서비스(Store)가 같은 재고를 바라보게 되므로 창고 작업과 재고 약속(가용 재고 계산·예약)을 분리한다.
- 여러 채널이 같은 재고를 동시에 약속해도 초과 판매가 나지 않도록, 가용 재고 계산과 예약을 inventory 서비스 한 곳에서만 수행한다.

## 2. 책임 범위

| 구분 | inventory 서비스가 한다 | inventory 서비스가 하지 않는다 (WMS 책임) |
|------|-----------|------------------------------|
| 재고 | 창고 × 상품 × Lot × 품질 상태 단위의 총 수량·예약 수량·가용 수량 관리 | Zone / Location / Capacity, 적재 위치 결정 |
| 예약 | 예약 생성·연장·확정·해제·만료, Lot 할당(유통기한 오름차순) | 예약 확정 후 피킹·출고 작업, 현장 취소 가능 여부 판단 |
| 입고·반품·폐기 | WMS가 확정한 결과를 재고 수량에 반영 | 입고 예정, 검수, 적재, 반품 접수·검수, 폐기 신청·승인·이동 |
| 조정 | 실사 결과·대사 불일치에 따른 수량 조정의 승인 기준 적용과 확정 | 실사 계획·스냅샷·현장 카운트·차이 산정 |
| Lot / 유통기한 | Lot 상태(정상/임박/경과) 판정, 품질 상태 전환 배치 | 폐기 처리장으로의 물리 이동 |
| 마스터 데이터 | 상품 마스터(상품 자체 정보) | 창고 마스터, 카테고리 → Zone 매핑 |
| 이력·이벤트 | 수량 변동 이력(원장), 예약 이벤트 이력, 재고 변동 이벤트 발행 | 작업 이력(검수, 피킹 등) |
| 출고 이후 | 출고 확정 시점에 총 수량 차감까지만 수행 | (inventory 서비스·WMS 모두 범위 밖) 가맹점 등 출고 이후 재고 추적 |

## 3. 연동 서비스

| 서비스 | 관계 | 방향 |
|--------|------|------|
| WMS | 입고·출고·반품·폐기 확정, 실사 조정을 inventory 서비스에 요청. 예약 확정·Lot·상품 이벤트를 구독 | WMS → inventory 서비스 (동기 API), inventory 서비스 → WMS (이벤트) |
| OMS (예정) | 가용 재고 조회, 주문 단위 예약·확정·해제 | OMS → inventory 서비스 (동기 API), inventory 서비스 → OMS (이벤트) |
| 가맹점 서비스(Store) | 가맹점 발주 시 가용 재고 조회·예약. 점주 권한 확인은 Store가 담당 | Store → inventory 서비스 (동기 API), inventory 서비스 → Store (이벤트) |
| 어드민 콘솔 | 재고 담당자의 재고 조회, 조정·보정 승인 | 콘솔 → inventory 서비스 (직원 토큰) |
| dozy-auth | 토큰 검증(JWT, RS256), system client 발급 | inventory 서비스 → dozy-auth (스타터) |

## 4. 핵심 원칙

| # | 원칙 | 의미 |
|---|------|------|
| 1 | **입고 확정된 재고만 다룬다** | 입고 예정 수량(incoming)은 inventory 서비스가 알지 못하고 가용 재고에 포함하지 않는다. 입고 예정 재고를 미리 파는 시나리오(선주문·백오더)는 가정하지 않는다. |
| 2 | **위치를 모른다** | inventory 서비스는 창고 단위 수량까지만 안다. Zone·Location은 WMS만 안다. |
| 3 | **약속은 예약으로만 한다** | 가용 재고 조회 결과는 약속이 아니다. 채널은 반드시 예약을 확정해야 약속이 성립한다. |
| 4 | **수량·이력·이벤트는 한 트랜잭션** | 수량 변경, 재고 이력, 발행할 이벤트(Outbox)는 같은 트랜잭션으로 저장한다. 수량만 바뀌고 기록이 없는 상태를 허용하지 않는다. |
| 5 | **모든 변경 요청은 멱등하다** | 같은 멱등 키의 재요청은 같은 결과를 반환하고 수량을 중복 반영하지 않는다. 재시도와 이벤트 중복 전달을 전제로 한다. |
| 6 | **수량은 정해진 경로로만 바꾼다** | 입고·출고·반품·폐기 확정, 실사 조정, 대사 보정 외의 수동 수정 경로를 두지 않는다. 조정은 승인 기준을 거친다. |
| 7 | **물리 사실은 WMS가 기준이다** | 실물과 어긋나면 WMS 수량을 기준으로 inventory 서비스를 맞춘다. 자동 보정은 하지 않고 사람이 원인을 확인한 뒤 승인한다. |
| 8 | **현장을 inventory 서비스 장애에 묶지 않는다** | inventory 서비스가 장애여도 WMS의 입고·출고·반품 확정은 진행하고 재전송한다. inventory 서비스의 판단이 필요한 작업(조정, Lot 재할당)만 대기한다. |
| 9 | **되돌릴 수 없는 일은 사람이 승인한다** | 폐기 신청은 자동 연계해도 승인은 사람이 한다. 대사 보정은 항목별 승인이며 일괄 승인하지 않는다. |
| 10 | **다른 서비스의 데이터는 ID로만 참조한다** | 창고는 ID로만 참조하고, 상품 ID는 불투명한 식별자로 다룬다. 다른 서비스의 DB를 직접 조회하거나 JOIN하지 않는다. |
| 11 | **리소스 인가를 서비스가 직접 한다** | 토큰의 role로 기능 인가를, inventory 서비스 자체 데이터로 창고 접근 인가를 한다(`dozy-auth` 필수 규칙). |
| 12 | **출고 이후는 추적하지 않는다** | 출고가 확정되면 총 수량을 차감하는 것으로 inventory 서비스의 책임이 끝난다. 가맹점이 보유한 재고, 이동 중 재고, 가맹점의 소비 차감은 관리하지 않는다. |

## 5. 미확정 항목

- 🔶 캐시 도입 시점(가용 재고 조회 부하를 실측한 뒤 결정)
- `reservation.channel`은 값을 확정하지 않고 자유 문자열로 받는다. 채널별 TTL 상한은 설정 맵과 `default`로 둔다(ADR-0022). 서비스명이 확정되면 설정만 바꾼다
- 🔶 `dozy-auth` 프로젝트 작업: `inventory` audience 추가, `inventory:service`·`inventory:warehouse_manager`·`inventory:admin` role 등록(ADR-0011), system client(`svc-wms`, `svc-oms`, `svc-store`) 등록
